在关系型数据库中，子查询（Subquery / Nested Query） 指嵌套在另一个 SQL 查询内部的 SELECT 语句。

# 分类：按“返回结果的物理形状”分类
```
                        ┌── 标量子查询 (单行单列: 1×1 单元格)
                        ├── 列子查询   (多行单列: N×1 向量)
【子查询物理形状分类】 ─────┤
                        ├── 行子查询   (单行多列: 1×N 记录)
                        └── 表子查询   (多行多列: N×M 临时表)
```

## 标量子查询（Scalar Subquery）
- 特征
返回恰好 1 行 1 列的单一数值（如一个数字、一个字符串）

- 使用位置和操作符
常用于 SELECT 列表、WHERE 或 HAVING 的比较条件中（支持 **=, >, <, >=, <=, !=**）。

## 列子查询（Column Subquery）
- 特征：返回 N 行 1 列 的列表（一个单列数据集合）。

- 使用位置：通常配合集合操作符使用，如 **IN、NOT IN、ANY / SOME、ALL**。

- 常用操作符解析：

    - IN：外层的值存在于子查询返回的列表中。

    - ALL(...)：比子查询返回列表里的最大值还要大。

    - ANY(...) / > SOME(...)：只要比子查询返回列表里的最小值大即可。

## 行子查询（Row Subquery）
- 特征：返回 1 行 N 列 的记录。

- 使用语法：利用 SQL 的多列元组比较语法 (col1, col2) = (val1, val2)。

```sql
SELECT name, department_id, job_title 
FROM employees 
WHERE (department_id, job_title) = (
    SELECT department_id, job_title FROM employees WHERE name = '张三'
);
```

## 表子查询（Table Subquery / Derived Table）
特征：返回 N 行 M 列 的结果集，本质上是一张在内存中生成的派生表（Derived Table）。

使用位置：必须放在 FROM 之后，且在 MySQL 中必须强制赋予一个别名（否则抛出语法错误 Every derived table must have its own alias）。

```sql
SELECT t.department_id, t.avg_salary
FROM (
    SELECT department_id, AVG(salary) AS avg_salary 
    FROM employees 
    GROUP BY department_id
) AS t  -- 👈 必须起别名 t
WHERE t.avg_salary > 10000;  -- 查找部门平均工资大于10000的部门
```


# 分类：按“对外层查询的依赖关系”分类（核心性能水岭）
```
                   ┌── 独立/非相关子查询 (Non-Correlated Subquery)
                   │   └─> 内层只执行一次，结果缓存给外层复用 (高效)
【子查询依赖关系】————|
                   └── 相关子查询 (Correlated Subquery)
                       └─> 外层每读一行，内层重新执行一次 (极低效 $O(N \times M)$)
```

## 1. 独立/非相关子查询（Non-Correlated Subquery）
- 定义：子查询内部的语句完全独立，不依赖外层查询的任何字段。
- 执行物理逻辑：
    - MySQL 优先独立执行子查询，算出结果；
    - 将结果保存在内存或直接替换为常量；
    - 外层查询利用该常量/结果集进行检索。
- 物理复杂度：$O(N + M)$，性能可控。

## 2. 相关子查询（Correlated Subquery）—— 高危陷阱
- 定义：子查询内部引用了外层查询的别名/字段（即子查询依赖了主查询当前正在扫描的行数据）。

- 典型语法：EXISTS 或在子查询的 WHERE 中包含了外层表的主键（如 WHERE i.user_id = o.id）。

- 致命的物理循环逻辑（双重循环/嵌套循环）：
```
外层扫描驱动表 (主查询 N 行)
   │
   ├── 读第 1 行 (u.id = 1) ────> 传入子查询，子查询去磁盘/索引检索 1 次
   ├── 读第 2 行 (u.id = 2) ────> 传入子查询，子查询去磁盘/索引检索 1 次
   ├── ...
   └── 读第 N 行 (u.id = N) ────> 传入子查询，子查询去磁盘/索引检索 1 次
```
- 物理复杂度：O(N * M)!
如果外层表有 10 万行，子查询就要被强行重复驱动执行 10 万次。如果子查询字段没有索引，整个数据库的 CPU 和磁盘 I/O 会瞬间爆表。

- 案例：查出每个部门中薪水高于本部门平均薪水的员工
```sql
SELECT e1.name, e1.salary, e1.department_id
FROM employees e1
WHERE e1.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e1.department_id = e2.department_id
)

```


# 常用的操作符
1. 标量比较操作符
=（等于）、!= 或 <>（不等于）、>（大于）、<（小于）、>=（大于等于）、<=（小于等于）

2. 集合匹配操作符：IN 与 NOT IN

3. 存在性测试操作符：EXISTS 与 NOT EXISTS
EXISTS： 存在

NOT EXISTS： 不存在

4. 量词修饰操作符：ANY / SOME 与 ALL
```
┌── > ANY(...)  ──> 大于子查询列表里的【最小值】 (只要比其中任意一个大即可)
├── < ANY(...)  ──> 小于子查询列表里的【最大值】
│
├── > ALL(...)  ──> 大于子查询列表里的【最大值】 (必须比里面每一个都大)
└── < ALL(...)  ──> 小于子查询列表里的【最小值】
```

5. 元组比较操作符
使用形式：(col1, col2) = (SELECT colA, colB ...) 或 (col1, col2) IN (SELECT colA, colB ...)


操作符 | 子查询返回形状 | 物理执行特点 | 常见替代/优化方案 | 
| --  |  --  |  --  |  --  | 
= / > / < | 1 行 1 列 | 匹配单值，超行会崩溃报错 | 确保子查询带主键/唯一索引或聚合函数 | 
IN | N 行 1 列 | 适合外表大、子查询结果集小 | 现代 MySQL 自动改写为 Semi-JOIN | 
NOT IN | N 行 1 列 | 慎用！ 遇到 NULL 返回空 | 必须加 IS NOT NULL 或改为 NOT EXISTS | 
EXISTS | 布尔值 (T/F) | 短路机制，找到第一条就返回 | 适合外表小、子查询表大且关联字段有索引 | 
ANY / ALL | N 行 1 列 | 集合多值比较 | 建议改写为 MIN() / MAX() 聚合比较 | 
"(a, b) IN" | N 行 M 列 | 元组多列一次性比对 | 可用 JOIN ON a=x AND b=y 替代 | 

## EXISTS vs IN
1. IN 的执行逻辑
- 先把子查询里的结果集一次性全量查出来并在内存中构建 Hash/TempTable；
- 然后扫描外层表，拿着外层表的数据去子查询结果集中做匹配。
- 适用规律：外层表大，子查询结果集小（如：外层 100 万条，子查询只返回 10 条）。

2. EXISTS 的执行逻辑
- EXISTS 只关心子查询“有没有数据返回”（一旦找到第一条符合条件的物理行就立刻中断返回 TRUE，称为短路机制 Short-circuiting）。

- 它的物理逻辑是外层驱动内层（相关子查询）。

- 适用规律：外层表小，子查询表大且关联字段建有高效率索引。


# 子查询优化（三大终极改写方案）
## 1. 将子查询改写为 JOIN 拼表（最常见）
## 2. 利用 CTE / WITH 语法
当子查询逻辑极其复杂、需要在多个地方重复引用时，使用 MySQL 8.0+ 支持的 WITH 公用表表达式（CTE）。
```sql
WITH DeptAvgSalary AS (
    SELECT department_id, AVG(salary) AS avg_sal
    FROM employees
    GROUP BY department_id
)
SELECT e.name, e.salary, d.avg_sal
FROM employees e
JOIN DeptAvgSalary d ON e.department_id = d.department_id
WHERE e.salary > d.avg_sal;
```

## 3. 利用窗口函数（Window Functions）彻底消灭子查询
```sql
SELECT id, name, department_id, salary
FROM (
    SELECT id, name, department_id, salary,
           DENSE_RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) as rk
    FROM employees
) t
WHERE t.rk = 1;
```

## 总结
1. 能用 窗口函数 替代的组内计算，无脑选窗口函数（一次扫描完成）；
2. 能用 JOIN 替代的相关子查询，优先改写为 JOIN（让优化器掌控驱动顺序）；
3. 需要提取临时表时，优先使用 WITH (CTE) 增强可读性；
4. 必须使用子查询时，务必确保子查询关联条件命中 B+ 树索引，防止产生 $O(N \times M)$ 循环遍历。
