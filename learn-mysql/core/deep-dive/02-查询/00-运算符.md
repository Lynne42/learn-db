# 常用操作符

## 常用比较运算符：
=, !=, >, <, >=, <=

## 范围与集合
运算符 | 含义 | 
| -- | -- |
BETWEEN ... AND ... | |
IN (val1, val2) | IN可以理解为一组等值比较，比较结果通过通过 `OR` 连接 |
NOT IN(val1, val2, NULL) | NOT IN 可以理解为 先对数据使用IN操作，对操作结果使用 NOT |

### IN 和 NOT IN
```sql
user_id IN (2, NULL)

-- 逻辑等价于
user_id = 2 OR user_id = NULL
```

相应地：

```sql
user_id NOT IN (2, NULL)

-- 逻辑等价于
NOT (user_id = 2 OR user_id = NULL)
```

假设 `user_id = 1`：

```text
1 = 2                  → FALSE
1 = NULL               → UNKNOWN
FALSE OR UNKNOWN       → UNKNOWN
NOT UNKNOWN            → UNKNOWN
WHERE UNKNOWN          → 当前行被过滤
```

## 字符串匹配与空值

运算符 | 含义 | 示例 | 说明与优化路径 | 
--  | --  | --  |  -- | 
IS NULL | 判断是否为空 | WHERE email IS NULL | 判断字段值是否为物理 NULL（不能用 = NULL）。 | 
IS NOT NULL | 判断是否非空 | WHERE email IS NOT NULL | 判断字段是否有值。 | 
LIKE | 模糊匹配 | WHERE name LIKE '张%' | 左前缀原则：'张%'（右模糊）走索引；'%张'（左模糊）导致索引全表失效。 | 
正则匹配 REGEXP | | | |

### LIKE 模糊匹配
`LIKE` 基于通配符进行简单的模式匹配：
- `%`：代表任意长度（包括 0）的任意字符。
- `_`：代表有且仅有一个的任意字符。'a_'， 匹配 "'ab', 'ac', 'a1' (以 a 开头的双字符)" 

### REGEXP 正则匹配
当 `LIKE` 表达能力不足时，可以使用 `REGEXP`（或 `RLIKE`）。它支持标准的正则表达式语法（如 `^`, `$`, `[0-9]`, `+` 等）。
*注意：在大型数据集上，`REGEXP` 的 CPU 计算开销比 `LIKE` 大得多，且无法利用索引。*


## 逻辑运算
运算符 | 含义 | 示例 | 底层行为与崩溃点 | 
-- | -- | -- | -- |
AND | 逻辑与（且） | status = 1 AND age > 18 | 短路求值：左边为假，右边直接不执行。优化器会优先评估走索引的条件。 | 
OR | 逻辑或（或） | status = 1 OR role = 'admin' | 致命崩溃点：如果 OR 两边的字段不全是索引，会导致索引失效转为全表扫描。 | 
NOT 或 ! | 逻辑非（取反） | NOT (status = 1) | 改变条件的真假性。通常会导致索引失效，尽量避免对索引列取反。 | 

### AND 运算符在 TRUE/FALSE/UNKNOWN之间的计算

只要一侧确定为 FALSE，整体一定为 FALSE；否则 UNKNOWN 会继续传播。

| AND | TRUE | FALSE | UNKNOWN |
|---|---:|---:|---:|
| **TRUE** | TRUE | FALSE | UNKNOWN |
| **FALSE** | FALSE | FALSE | FALSE |
| **UNKNOWN** | UNKNOWN | FALSE | UNKNOWN |

### OR 运算符在 TRUE/FALSE/UNKNOWN之间的计算
只要一侧确定为 TRUE，整体一定为 TRUE；否则 UNKNOWN 会继续传播。

| OR | TRUE | FALSE | UNKNOWN |
|---|---:|---:|---:|
| **TRUE** | TRUE | TRUE | TRUE |
| **FALSE** | TRUE | FALSE | UNKNOWN |
| **UNKNOWN** | TRUE | UNKNOWN | UNKNOWN |

### NOT 运算符在 TRUE/FALSE/UNKNOWN之间的计算

- `NOT TRUE` 是 `FALSE`
- `NOT FALSE` 是 `TRUE`
- `NOT UNKNOWN` 仍是 `UNKNOWN`。
否定一个未知结论，并不能把它变成确定结论。


## 算数运算法
运算符含义 | 示例 | 架构师警告 | 
--  |  --  |  --  | 
"+, -" | 加、减 WHERE price - 10 > 100 | 严禁在索引列上直接进行算术运算！ | 
"*, /" | 乘、除,WHERE score * 2 >= 180 | 同上。 | 
% 或 MOD | 取模（求余）,WHERE id % 2 = 0, | 常用在分库分表或数据抽样场景，同样不走索引。 | 


## 位运算符
运算符 | 含义 | 示例 | 底层行为 | 
--  |  -- | -- | -- | 
& | 位与（AND） | WHERE (tags & 4) > 0,校验二进制特定位是否为 1（如校验是否有某权限）。 | 
"\|" | 位或（OR） | SET tags = tags | 1,通常用在 UPDATE 中用于勾选或开启某状态。 | 
^ | 位异或（XOR） | WHERE (tags ^ 1) = 0 | 两个位不同则为 1。 | 
~ | 位取反 | ~tags | 翻转所有二进制位。 | 


## 操作符优先级
MySQL 的底层解析优先级是：

$$\text{算术运算符}\ > \text{比较运算符} \ > \text{NOT} \ > \text{AND} \ > \text{OR}$$
