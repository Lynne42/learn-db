# 基本DQL查询语法骨架
```sql
SELECT [DISTINCT] 字段列表
FROM 表名
[(LEFT / RIGHT) JOIN 关联表 ON 关联条件]
[WHERE 单行筛选条件]
[GROUP BY 分组字段]
[HAVING 分组后筛选条件]
[ORDER BY 排序字段 ASC|DESC]
[LIMIT 偏移量, 条数];
```

# DQL 的“语法书写顺序” vs “物理执行顺序”
## 物理执行顺序对照图

书写顺序：
```
1. SELECT 字段列表
2. FROM 表名
3. WHERE 条件
4. GROUP BY 分组字段
5. HAVING 分组后条件
6. ORDER BY 排序字段
7. LIMIT 截取条数
```

【引擎底层的实际执行顺序】:

```
1. FROM         (确定数据源/加载表)
2. ON / JOIN    (多表联查匹配，产生笛卡尔积/过滤)
3. WHERE        (对原始数据进行单行过滤)
4. GROUP BY     (将过滤后的数据进行分组)
5. HAVING       (对分组汇总后的结果再次过滤)
6. SELECT       (提取指定的列、计算表达式、去重)
7. DISTINCT     (去重)
8. ORDER BY     (对最终提取出的结果集排序)
9. LIMIT        (物理截取指定条数返回)
```

1. GROUP BY 和 HAVING 通常是联合使用
2. SELECT 执行的顺序比较靠后， 所以SELECT语句中定义的别名， 在 2(ON / JOIN)， 3(WHERE)， 4(GROUP BY)， 5(HAVING) 步骤中都不能使用， 而在 8中可以使用别名
3. WHERE 
    - WHERE中不能使用聚合函数(比如 MAX, MIN, AVG等等)， 因为聚合是在 第4和5步才出现的， 而WHERE所在的第3步还没有出现聚合的结果， 所以不能在这里对聚合函数进行过滤
    - SQL查询的结果有3种， TRUE，FALSE，UNKNOWN， WHERE过滤条件只保留结果为TRUE的数据

# DQL查询评估机制

多数编程语言中的布尔表达式只有真和假。SQL 还必须表达“数据未知”，因此增加了 `UNKNOWN`：

| 条件示例 | 结果 | 原因 |
|---|---|---|
| `1 = 1` | `TRUE` | 两个确定值相等 |
| `1 = 2` | `FALSE` | 两个确定值不等 |
| `1 = NULL` | `UNKNOWN` | 无法判断未知值是否等于 1 |
| `NULL = NULL` | `UNKNOWN` | 两个未知值不代表同一个确定值 |
| `NULL IS NULL` | `TRUE` | `IS NULL` 判断的是空值状态 |

`WHERE`、`HAVING` 和 JOIN 过滤条件只接受结果为 `TRUE` 的行。`FALSE` 与 `UNKNOWN` 都不会进入结果集，但二者的语义不同，后续再进行逻辑运算时结果也可能不同。

只有当 `WHERE`、`HAVING` 和 JOIN 的计算结果为 True, 才会返回该条数据，遇到数据是NULL等的， 评估都是UNKNOWN, 不会返回该条数据
