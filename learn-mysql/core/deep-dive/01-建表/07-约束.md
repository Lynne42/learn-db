# 约束分类
按功能与数据完整性维度，数据库约束主要分为以下 6 大核心类型：
```text
                           ┌── 1. 主键约束 (PRIMARY KEY)    : 唯一且非空 (标识唯一实体)
                           ├── 2. 唯一约束 (UNIQUE)         : 唯一但可空 (防重)
                           ├── 3. 非空约束 (NOT NULL)       : 必须有值
【数据库 6 大核心约束分类】 ───┼── 4. 默认值约束 (DEFAULT)     : 未输入时自动填充
                           ├── 5. 检查约束 (CHECK)          : 值的范围/格式校验 (MySQL 8.0+)
                           └── 6. 外键约束 (FOREIGN KEY)    : 维持父子表引用完整性
```

## 1. 主键约束 (PRIMARY KEY)
- 物理特征：唯一（UNIQUE） + 非空（NOT NULL）。一张表有且仅有一个主键约束。

- 底层原理：在 InnoDB 中，主键约束是直接用来构建“聚簇索引（Clustered Index）”的。如果不显式指定，MySQL 会寻找唯一非空索引或隐式创建 DB_ROW_ID。

```sql
CREATE TABLE users (
    id BIGINT UNSIGNED  AUTO_INCREMENT,
    PRIMARY KEY (id) -- 声明为主键
);
```

## 2. 唯一约束（UNIQUE）
- 物理特征：保证该列或多列组合的值在全表中必须唯一，但允许存在 NULL 值（注意：在 MySQL 中，NULL 不等于 NULL，因此唯一列中可以插入多个 NULL）。

- 底层原理：会自动为其创建一个唯一二级索引（Unique Secondary Index）。每次执行 INSERT/UPDATE 时，InnoDB 会去索引树上校验是否存在冲突。

```sql
CREATE TABLE users (
    id BIGINT UNSIGNED PRIMARY KEY,
    email VARCHAR(128),
    CONSTRAINT uk_email UNIQUE (email) -- 唯一约束，防重
);
```

## 3. 非空约束（NOT NULL）
- 物理特征：强制该列在插入或更新时必须赋予具体值，不能为 NULL。

- 物理底层：在 InnoDB 的行头（Compact/Dynamic 行格式）中，存在一个 NULL 值列表 BitMap。指定 NOT NULL 的列不会占用 NULL 位图空间，且能让索引 B+ 树的统计和比较更加高效。

```sql
CREATE TABLE users (
    username VARCHAR(64) NOT NULL -- 强制非空
);
```

## 4. 默认值约束（DEFAULT）
物理特征：当插入数据时若未显式为该列赋值，数据库会自动使用预先设定的默认值填充。

```sql
CREATE TABLE users (
    status TINYINT UNSIGNED NOT NULL DEFAULT 1, -- 默认状态为 1 (正常)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP -- 默认使用当前系统时间
);
```

## 5. 检查约束（CHECK）
物理特征：通过指定布尔表达式，强制限制列中允许写入的数据范围或模式。（注意：MySQL 5.7 及之前会忽略 CHECK 语法，MySQL 8.0+ 正式物理支持并生效。）

```sql
CREATE TABLE users (
    age INT UNSIGNED,
    gender VARCHAR(10),
    CONSTRAINT chk_age CHECK (age >= 0 AND age <= 150), -- 限制年龄范围
    CONSTRAINT chk_gender CHECK (gender IN ('MALE', 'FEMALE', 'OTHER'))
);
```

## 6. 外键约束（FOREIGN KEY）
- 物理特征：建立在“从表（子表）”上，指向“主表（父表）”的主键或唯一键。用于保障多表之间的参照完整性（Referential Integrity）。

- 物理动作（回忆前述）：当父表发生 DELETE 或 UPDATE 时，可触发 CASCADE（级联清理）、SET NULL（置空）、RESTRICT（严格阻止报错）。

```sql
CREATE TABLE orders (
    id BIGINT UNSIGNED PRIMARY KEY,
    user_id BIGINT UNSIGNED,
    CONSTRAINT fk_orders_user 
    FOREIGN KEY (user_id) REFERENCES users(id)
    ON DELETE RESTRICT -- 只要用户有订单，拒绝删用户
);
```

# 单列约束 vs 复合约束（按作用范围分类）
## 1. 单列约束
作用于单一字段：
```sql
CREATE TABLE example (
    phone VARCHAR(20) UNIQUE -- 仅限制 phone 字段唯一
);
```

## 2. 复合/联合约束（Composite Constraint）
作用于多个字段的组合，要求多列组合起来的值不能重复：

```sql
CREATE TABLE project_members (
    project_id BIGINT UNSIGNED,
    user_id BIGINT UNSIGNED,
    role VARCHAR(32),
    -- 联合主键：项目ID + 用户ID 组合唯一（同一个用户不能重复加入同一个项目）
    PRIMARY KEY (project_id, user_id),
    -- 联合唯一约束
    CONSTRAINT uk_proj_user UNIQUE (project_id, user_id)
);
```

# 约束的操作 DDL
```sql
-- 1. 添加非空约束 / 默认值
ALTER TABLE users MODIFY COLUMN age INT NOT NULL DEFAULT 18;

-- 2. 添加唯一约束
ALTER TABLE users ADD CONSTRAINT uk_phone UNIQUE (phone);

-- 3. 添加外键约束
ALTER TABLE orders ADD CONSTRAINT fk_user FOREIGN KEY (user_id) REFERENCES users(id);

-- 4. 删除唯一约束（本质是删除其背后的二级索引）
ALTER TABLE users DROP INDEX uk_phone;

-- 5. 删除外键约束
ALTER TABLE orders DROP FOREIGN KEY fk_orders_user;

-- 6. 删除主键约束
ALTER TABLE users DROP PRIMARY KEY;
```
