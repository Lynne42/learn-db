# 数据架构
> 数据架构的核心，是明确数据所有权，用约束保证正确性，用事务保证局部原子性，用幂等和状态机控制流程，用任务、重试和补偿实现最终一致性，再通过审计与监控保证全链路可追溯。

设计一个数据模块时，至少回答下面的问题:
1. 数据由谁生产、谁维护？
2. 哪些是源数据，哪些是过程数据，哪些是最终事实？
3. 业务对象如何唯一识别？
4. 重复请求如何处理？
5. 主表和明细表如何拆分？
6. 状态如何流转，哪些跳转非法？
7. 哪些操作必须放在同一事务？
8. 哪些外部操作无法被数据库事务覆盖？
9. 失败后是重试、回滚还是人工补偿？
10. 定时任务重复执行是否安全？
11. 多实例是否会并发处理同一数据？
12. Redis数据丢失是否会破坏业务事实？
13. 文件生成和数据库写入如何对账？
14. 每次关键操作能否追溯到用户和时间？
15. 配置修改是否有校验、版本和审计？
16. 敏感信息是否被安全保存？
17. 系统能否监控积压、延迟和失败？
18. 能否从源数据追踪到最终结果和反馈？


# 名词解释
| 名词 | 通俗解释 |
|---|---|
| 数据所有权 | 明确一份数据由哪个系统产生、维护并对正确性负责。 |
| 主键（Primary Key） | 数据库中唯一标识一条记录的字段，例如 `id`。 |
| 业务键（Business Key） | 业务上识别对象的编号，例如订单号、批次号。 |
| 外键（Foreign Key） | 表与表之间的关联字段，例如明细表通过 `batch_id` 关联批次表。 |
| 唯一约束（Unique Constraint） | 从数据库层禁止重复数据，是实现幂等的重要手段。 |
| 索引（Index） | 用额外存储空间换取查询速度的数据结构；不是越多越好。 |
| 事务（Transaction） | 多个数据库操作要么全部成功，要么全部回滚。 |
| 状态机（State Machine） | 规定业务对象有哪些状态，以及允许怎样从一个状态转到另一个状态。 |
| 幂等（Idempotency） | 同一个请求执行一次或重复执行多次，最终业务结果相同，不会产生重复数据。 |
| 定时任务（Scheduled Job） | 按固定时间或周期自动执行的任务，例如每小时同步一次数据。 |
| 时间窗口（Time Window） | 定时任务本次需要处理的数据时间范围，例如 `[10:00, 11:00)`。 |
| Redis | 高速内存数据库，通常用于缓存、短期锁、Session和临时状态，不保存唯一业务事实。 |
| 分布式锁（Distributed Lock） | 多个服务实例竞争同一任务时，保证同一时刻只有一个实例执行。 |
| 最终一致性（Eventual Consistency） | 数据库、文件和外部系统无法同时提交时，允许短暂不一致，通过重试和补偿最终达到一致。 |
| 审计日志（Audit Log） | 记录谁在什么时候对什么数据做了什么修改，用于追溯。 |

关系：
```
主键、外键、唯一约束、索引
→ 保证表结构和查询能力

事务、状态机、幂等
→ 保证业务处理正确

定时任务、时间窗口、分布式锁
→ 保证自动任务正确执行

Redis
→ 提供临时控制和访问加速

最终一致性
→ 处理数据库与外部系统之间的一致性

审计日志
→ 保证整个过程可追溯
```

## P0：必须掌握

1. **数据所有权（Data Ownership）**：哪套系统负责产生、维护并解释数据。
2. **实体（Entity）**：业务中需要保存的对象，如用户、订单、任务。
3. **字段（Column）**：实体的一个属性。
4. **表（Table）**：同类实体的结构化集合。
5. **主键（Primary Key）**：唯一标识一条记录。
6. **业务键（Business Key）**：业务上唯一识别对象的字段。
7. **外键（Foreign Key）**：建立表与表之间的关联。
8. **唯一约束（Unique Constraint）**：从数据库层禁止业务重复。
9. **非空约束（NOT NULL）**：强制字段必须有值。
10. **默认值（Default Value）**：插入时未传值所使用的初始值。
11. **索引（Index）**：提高查询速度的数据结构。
12. **联合索引（Composite Index）**：由多个字段组成的索引。
13. **事务（Transaction）**：多个操作全部成功或全部回滚。
14. **ACID**：事务的原子性、一致性、隔离性、持久性。
15. **提交（Commit）**：确认事务中的修改。
16. **回滚（Rollback）**：撤销事务中的修改。
17. **状态（Status）**：业务对象当前所处阶段。
18. **状态机（State Machine）**：定义合法状态及状态转换规则。
19. **幂等（Idempotency）**：重复执行不会产生重复业务结果。
20. **审计日志（Audit Log）**：记录谁在何时修改了什么。
21. **数据源（Data Source）**：系统访问的一套数据库或外部数据来源。
22. **主库/从库（Master/Slave）**：分别承担主要写入和读取等职责的数据库。

## P1：后台系统必须掌握

23. **一对一、一对多、多对多**：实体之间的三类基本关系。
24. **主表/明细表（Header/Detail）**：一个业务批次与多条明细的建模方式。
25. **规范化（Normalization）**：减少数据重复和更新异常。
26. **反规范化（Denormalization）**：为查询性能适度冗余数据。
27. **冗余字段（Redundant Field）**：为提高查询效率重复保存的数据。
28. **数据字典（Data Dictionary）**：定义字段、状态和枚举值的含义。
29. **枚举（Enum）**：取值范围固定的业务字段。
30. **分页（Pagination）**：分批查询大量数据。
31. **游标分页（Cursor Pagination）**：通过上次位置继续查询，适合大数据量。
32. **查询计划（Execution Plan）**：数据库实际采用的查询执行方式。
33. **EXPLAIN**：分析SQL是否使用索引及扫描量的工具。
34. **慢查询（Slow Query）**：执行时间超过阈值的SQL。
35. **锁（Lock）**：控制并发修改同一份数据。
36. **乐观锁（Optimistic Lock）**：用版本号判断数据是否被别人修改。
37. **悲观锁（Pessimistic Lock）**：操作前直接锁住数据。
38. **死锁（Deadlock）**：多个事务相互等待对方释放资源。
39. **隔离级别（Isolation Level）**：控制事务之间能看到多少未完成修改。
40. **脏读（Dirty Read）**：读到其他事务尚未提交的数据。
41. **不可重复读（Non-repeatable Read）**：同一事务两次读取同一行结果不同。
42. **幻读（Phantom Read）**：同一事务两次范围查询得到的行数不同。

## P1：任务与流程必须掌握

43. **定时任务（Scheduled Job）**：按时间或周期自动执行的任务。
44. **Cron表达式**：描述定时任务执行时间的表达式。
45. **时间窗口（Time Window）**：一次任务需要处理的数据时间范围。
46. **半开区间 `[start,end)`**：包含开始、不包含结束，避免相邻窗口重复。
47. **任务执行记录（Job Run Record）**：保存任务开始、结束、结果和错误。
48. **触发方式（Trigger Type）**：区分自动、手动、重试等执行来源。
49. **Misfire**：系统停机等原因导致任务错过计划执行时间。
50. **补跑（Backfill）**：重新执行遗漏的历史时间窗口。
51. **重试（Retry）**：失败后再次执行。
52. **重试退避（Backoff）**：延迟并逐步拉长重试间隔。
53. **补偿（Compensation）**：通过反向或修复操作纠正部分失败。
54. **任务抢占（Task Claiming）**：多个执行器竞争时只允许一个获得任务。
55. **批处理（Batch Processing）**：一次处理一批数据。
56. **分片（Sharding/Partitioning Work）**：把大任务拆给多个执行器。

## P1：Redis与缓存必须掌握

57. **缓存（Cache）**：保存热点数据，减少数据库或外部调用。
58. **缓存命中/未命中（Hit/Miss）**：是否能直接从缓存取得数据。
59. **TTL**：缓存或锁的过期时间。
60. **Cache Aside**：应用先查缓存，未命中查数据库；更新后删除缓存。
61. **分布式锁（Distributed Lock）**：跨实例保证同一时刻只有一个执行者。
62. **原子操作（Atomic Operation）**：操作不可被分割或部分完成。
63. **缓存穿透**：大量查询数据库中不存在的数据。
64. **缓存击穿**：热点数据失效瞬间大量请求打到数据库。
65. **缓存雪崩**：大量缓存同时失效导致数据库压力激增。
66. **热点Key（Hot Key）**：访问量集中在少数Redis Key。
67. **大Key（Big Key）**：单个Key存储数据过大。
68. **分布式Session**：多个服务实例共享用户会话。

## P2：分布式系统核心

69. **本地事务（Local Transaction）**：只保证一个数据库内的事务。
70. **分布式事务（Distributed Transaction）**：跨数据库或服务的事务协调。
71. **强一致性（Strong Consistency）**：操作完成后所有读取立即看到相同结果。
72. **最终一致性（Eventual Consistency）**：允许短暂不一致，最终通过重试达到一致。
73. **CAP理论**：分布式系统在一致性、可用性和分区容错之间的权衡。
74. **BASE理论**：基本可用、软状态和最终一致性。
75. **消息队列（Message Queue）**：异步传递任务或业务事件。
76. **生产者/消费者（Producer/Consumer）**：发送和处理消息的两方。
77. **至少一次投递（At-least-once）**：消息可能重复，但不会轻易丢失。
78. **重复消费（Duplicate Consumption）**：同一消息被处理多次。
79. **消费幂等（Consumer Idempotency）**：重复消息不会产生重复结果。
80. **消息积压（Backlog）**：消息产生速度超过处理速度。
81. **死信队列（Dead Letter Queue）**：存放多次处理失败的消息。
82. **Outbox Pattern**：在业务事务中同时记录待发送事件，再异步投递。
83. **Saga**：通过多个本地事务和补偿操作完成跨服务业务流程。
84. **事件驱动架构（Event-Driven Architecture）**：系统通过事件连接各业务模块。
85. **同步调用/异步调用**：调用方是否等待下游处理完成。
86. **超时（Timeout）**：外部调用等待的最长时间。
87. **熔断（Circuit Breaker）**：下游持续故障时暂时停止调用。
88. **限流（Rate Limiting）**：限制单位时间内的请求量。
89. **降级（Degradation）**：故障时关闭非核心能力，保留核心服务。

## P2：数据集成与文件处理

90. **ETL**：抽取、转换、加载数据。
91. **ELT**：先加载原始数据，再在目标系统转换。
92. **数据同步（Data Synchronization）**：在不同系统之间复制数据。
93. **全量同步（Full Sync）**：每次处理全部数据。
94. **增量同步（Incremental Sync）**：只处理新增或变化数据。
95. **CDC（Change Data Capture）**：捕获数据库变更并同步。
96. **水位线（Watermark）**：记录增量任务已经处理到的位置。
97. **迟到数据（Late-arriving Data）**：晚于预期时间到达的数据。
98. **重复数据（Duplicate Data）**：同一业务事实被记录多次。
99. **数据对账（Reconciliation）**：比较两边数量、金额或明细是否一致。
100. **数据血缘（Data Lineage）**：数据从哪里来、经过什么处理、流向哪里。
101. **Schema Evolution**：数据结构随版本变化的管理方式。
102. **文件元数据（File Metadata）**：文件名、路径、大小、Hash、状态等信息。
103. **Checksum/Hash**：验证文件或数据内容是否一致。
104. **FTP/SFTP**：文件传输协议；SFTP通过SSH加密。
105. **对象存储（Object Storage）**：通过Bucket和Object Key保存文件。
106. **断点续传（Resume Transfer）**：传输失败后从中断位置继续。

## P2：架构与代码分层

107. **Controller**：处理路由、参数和权限。
108. **Service**：承载业务规则、事务和流程编排。
109. **Repository/Mapper**：负责数据库访问。
110. **DTO**：服务或接口之间传输的数据结构。
111. **VO**：面向页面或调用方展示的数据结构。
112. **Domain Model**：表达核心业务对象和规则的模型。
113. **DAO**：数据访问对象。
114. **Adapter**：把外部系统接口转换为内部可使用的形式。
115. **Client/Gateway**：封装HTTP、FTP、消息队列等外部调用。
116. **依赖倒置（Dependency Inversion）**：业务逻辑依赖接口，而非具体基础设施。
117. **高内聚（High Cohesion）**：同一模块内部职责紧密相关。
118. **低耦合（Low Coupling）**：不同模块减少直接依赖。
119. **单一职责（Single Responsibility）**：一个组件只承担一种主要职责。
120. **领域边界（Bounded Context）**：划分业务概念和数据归属的边界。

## P2：配置与版本

121. **配置中心（Configuration Center）**：集中管理运行配置。
122. **功能开关（Feature Flag）**：无需重新发布即可启停功能。
123. **配置版本（Configuration Version）**：记录配置每次变化。
124. **快照（Snapshot）**：某个时刻的完整数据副本。
125. **草稿（Draft）**：已保存但尚未生效的版本。
126. **发布（Publish）**：使配置或规则正式生效。
127. **回滚（Rollback Version）**：恢复到历史版本。
128. **灰度发布（Canary Release）**：先让少量用户或流量使用新版本。
129. **数据库迁移（Database Migration）**：受控地修改表结构或基础数据。
130. **向前兼容/向后兼容**：新旧版本能否相互处理数据。

## P2：安全与权限

131. **认证（Authentication）**：确认用户是谁。
132. **授权（Authorization）**：确认用户可以做什么。
133. **RBAC**：基于用户、角色、权限进行授权。
134. **数据权限（Data Scope）**：控制用户可以查看哪些数据。
135. **最小权限原则（Least Privilege）**：只授予完成工作所需的最少权限。
136. **敏感数据（Sensitive Data）**：密码、密钥、身份信息等高风险数据。
137. **数据脱敏（Masking）**：隐藏敏感字段的部分内容。
138. **静态加密（Encryption at Rest）**：数据落盘后的加密。
139. **传输加密（Encryption in Transit）**：通过TLS/SSH保护传输过程。
140. **密钥管理（Secret Management）**：安全保存、授权和轮换密钥。
141. **SQL注入（SQL Injection）**：输入内容被拼接为恶意SQL。
142. **SSRF**：利用服务器访问内部或受限制网络地址。
143. **路径穿越（Path Traversal）**：利用文件路径访问允许范围之外的文件。

## P3：数据治理与分析

144. **数据质量（Data Quality）**：数据是否准确、完整、一致、及时。
145. **完整性（Completeness）**：需要的数据是否缺失。
146. **准确性（Accuracy）**：数据是否符合真实业务。
147. **一致性（Consistency）**：不同表或系统是否表达相同事实。
148. **及时性（Timeliness）**：数据是否在要求时间内到达。
149. **有效性（Validity）**：数据是否符合格式和业务规则。
150. **主数据（Master Data）**：跨系统共享的核心基础对象。
151. **元数据（Metadata）**：描述数据结构、来源和含义的数据。
152. **数据目录（Data Catalog）**：集中查找和理解数据资产。
153. **数据保留策略（Retention Policy）**：数据保存多久、何时归档或删除。
154. **软删除（Soft Delete）**：用状态标记删除，保留原始记录。
155. **硬删除（Hard Delete）**：从数据库物理删除记录。
156. **归档（Archiving）**：将低频历史数据迁出在线表。
157. **数据生命周期（Data Lifecycle）**：数据从产生到销毁的全过程。

## P3：可观测性与可靠性

158. **日志（Logging）**：记录程序运行事件。
159. **指标（Metrics）**：可聚合的数值，如成功率和延迟。
160. **链路追踪（Tracing）**：追踪请求经过的多个服务。
161. **Trace ID**：标识一次完整调用链。
162. **可观测性（Observability）**：通过日志、指标、追踪理解系统状态。
163. **SLA**：服务对外承诺的可用性目标。
164. **SLO**：系统内部设定的服务目标。
165. **SLI**：衡量目标是否达成的指标。
166. **吞吐量（Throughput）**：单位时间处理的数据量。
167. **延迟（Latency）**：一次处理花费的时间。
168. **可用性（Availability）**：系统可以正常服务的时间比例。
169. **故障恢复（Recovery）**：系统从异常恢复正常的能力。
170. **RPO**：发生灾难时最多可以接受丢失多少时间的数据。
171. **RTO**：发生灾难后要求多长时间恢复服务。

## 学习顺序

按下面顺序分组学习：

1. **关系数据库基础**：实体、表、字段、主键、外键、约束、索引。
2. **业务正确性**：事务、状态机、幂等、审计日志。
3. **查询与并发**：分页、执行计划、锁、隔离级别。
4. **自动化处理**：定时任务、时间窗口、补跑、重试。
5. **缓存与并发控制**：Redis、TTL、缓存、分布式锁。
6. **跨系统一致性**：消息队列、最终一致性、Outbox、补偿。
7. **数据集成**：ETL、增量同步、CDC、水位线、对账、血缘。
8. **工程架构**：Controller、Service、Mapper、Adapter、领域边界。
9. **安全治理**：权限、密钥、加密、数据质量和生命周期。
10. **可靠性建设**：日志、指标、追踪、SLA、RPO、RTO。
