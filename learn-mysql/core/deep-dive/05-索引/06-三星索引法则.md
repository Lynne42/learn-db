# 三星索引法则（Three-Star System）

> 前置知识：[回表机制](./04-回表机制.md) — 理解为什么消除回表是索引设计的终极追求。

由数据库专家 O'Neil 提出的"三星索引"是顶级架构师设计索引的终极追求。对于一条特定的查询 SQL，如果一个索引能同时做到以下三点，它就是"满分索引"：

## ⭐ 一星：最小化扫描范围

将所有等值条件（如 `WHERE status = 1 AND zone = 'A'`）的列放在索引最前面。这样可以把查询范围瞬间缩小到磁盘的一小块地方。

**底层原理**：等值条件列在 B+ 树最左侧，意味着 InnoDB 可以通过精确匹配直接定位到一个极小的叶子节点区间，而非扫描大片连续页。

## ⭐⭐ 二星：消除排序（Avoid Sort）

如果 SQL 里有 `ORDER BY create_time`，把 `create_time` 顺着加到索引里。因为索引本身就是有序的，这样 MySQL 就不需要在内存中进行痛苦的物理排序（FileSort），直接顺着索引树拿结果。

**性能影响**：FileSort 在数据量大时会溢出到磁盘临时文件，产生大量随机 I/O。消除排序可以将查询性能提升一个数量级。

## ⭐⭐⭐ 三星：消除回表（Covering Index / 覆盖索引）

如果你的索引树里，已经包含了你 `SELECT` 后面需要的全部列，MySQL 就再也不需要拿着主键去查聚簇索引了（回表次数直接降为 0）。这种索引叫作覆盖索引，速度达到物理极限。

## 实战示例

```sql
-- 查询：找出某区域、状态为1的记录，按创建时间排序，只取 name
SELECT name FROM orders
WHERE zone = 'A' AND status = 1
ORDER BY create_time;
```

三星索引设计：

```sql
CREATE INDEX idx_zone_status_ctime_name ON orders(zone, status, create_time, name);
```

| 星级 | 怎么做到的 |
| -- | -- |
| ⭐ 一星 | `zone` 和 `status` 在最前面 → 精确定位 |
| ⭐⭐ 二星 | `create_time` 紧跟其后 → 天然有序，无需 FileSort |
| ⭐⭐⭐ 三星 | `name` 也在索引中 → 覆盖索引，零回表 |

> **现实中的取舍**：三星往往不可能同时满足（特别是当查询模式多样时）。优先级一般是 **一星 > 三星 > 二星**——先缩小范围，再消除回表，最后才考虑排序。
