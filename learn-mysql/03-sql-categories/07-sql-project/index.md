# 模块 03.07: SQL 基础闭环项目 — 订单系统最小可用版

> **模块定位**：前面的 DDL、DML、DQL、DCL 与 TCL 分别训练了单项能力。本模块把这些能力收束为订单系统 V1：先审计 Schema 契约，再完成核心查询，最后执行 CRUD 综合验收。

## 🎯 知识边界与生态位

**本模块覆盖：**

- 复盘用户、权限、商品目录、订单和订单明细的数据模型。
- 审计主键、唯一键、外键和关系边界。
- 使用 `INFORMATION_SCHEMA` 验证实际 Schema，而不是只相信设计文档。
- 组合订单列表、订单详情和用户消费统计查询。
- 从 Schema 初始化到 CRUD 验收的基础闭环。

**本模块不覆盖：**

- 索引选择、执行计划和查询性能，将在 04.01 以后展开。
- 并发事务、锁和库存竞争，将在 04.03 展开。
- 复杂查询表达、窗口函数和 CTE，将在 04.04 展开。
- 生产级安全、监控、备份和高可用。

## ⚡ 速查与避坑指南 (Cheat Sheet)

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| 查看建表契约 | `SHOW CREATE TABLE table_name` | `DESCRIBE` 不展示全部外键和索引细节。 |
| 查外键元数据 | `INFORMATION_SCHEMA.KEY_COLUMN_USAGE` | 必须限定 `TABLE_SCHEMA`，避免混入其他数据库。 |
| 恢复 Schema | 按版本号顺序执行 `schema/v*.sql` | 跳过中间 Migration 可能导致后续脚本失败。 |
| 订单详情 | 明确 Join Key 和结果粒度 | 一对多 Join 会放大行数，不能误当成订单数。 |
| 用户消费统计 | 先定义状态范围和聚合口径 | 是否包含取消、退款订单会直接改变指标含义。 |
| 综合验收 | 在隔离数据库中重建和验证 | 不要在持久化学习库中反复执行破坏性测试。 |
