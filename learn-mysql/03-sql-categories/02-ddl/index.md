# 模块 03.02: DDL — 数据定义语言

> **模块定位**：在明确了 SQL 语言的分集之后，DDL (数据定义语言) 是我们落地业务实体模型的第一步。要构建一个完整的电商订单系统，我们需要先划定物理存放的数据库，紧接着创建结构清晰、约束严格的实体表，并随时做好应对业务扩展而修改表结构的准备。本模块将专注于库和表的生命周期管理，带你从“怎么建库”开始，到“创建表并设定基础约束”，再到生产环境中“如何安全地变更表结构”。

## 🎯 知识边界与生态位

**本模块覆盖**：
- 数据库级 DDL：创建、删除数据库，以及利用 `ALTER DATABASE` 修改全局字符集与 Collation。
- 表级 DDL：创建表，并设定主键、NOT NULL、UNIQUE、CHECK 等基础物理约束。
- 结构变更 DDL：使用 `ALTER TABLE` 进行列的增删改、修改数据类型及重命名。
- 关系约束：技术主键、业务唯一键、外键、逻辑外键和多对多关联表。
- 优秀的工程习惯：编写 DDL 脚本时全面贯彻 `IF NOT EXISTS` / `IF EXISTS` 的防御性幂等写法。
- DDL 带来的元数据锁（Metadata Lock）及对于生产环境大表的变更风险直觉。

**本模块不覆盖**：
- 复杂的物理外键级联约束对事务和锁的深层负面影响（详见【模块 04.03】）。
- 索引（Index）在 DDL 中的底层物理设计与基于 B+ 树的扫描代价（详见【模块 04.01】）。
- 在海量数据表上进行 Online DDL 导致的数据库性能雪崩与第三方表结构变更工具（如 gh-ost/pt-osc）的实践（详见【模块 06.02】）。

## 🗺️ 完整知识地图 (Knowledge Map)

> 从架构师的视角，重新梳理本章知识点的因果关系。

| 核心知识点 | 本质/语法 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **防错性 DDL 语句** | `IF NOT EXISTS` | 用于在自动化流水线或多节点发布中确保脚本可以重复安全运行（实现**幂等性**），避免因对象已存在而导致发布流程中断报错。 | 03.02.00 |
| **库级字符集修改** | `ALTER DATABASE` | 用于修改数据库默认的编码属性。只影响以后在这个库下新创建的表，**已有的表不受任何影响**。 | 03.02.00 |
| **主键唯一性** | `PRIMARY KEY` | 表物理排序与唯一性保障。主键所对应的列绝对不能有 NULL 值，在 InnoDB 引擎中主键也是聚簇索引的物理边界，对查询起核心提速作用。 | 03.02.01 |
| **条件检查约束** | `CHECK (expr)` | MySQL 8.0 真正支持的字段级条件校验（例如 `price > 0`）。可以阻断不符合业务常理的数据写入，在物理数据库级别守护数据质量底线。 | 03.02.01 |
| **表级 DDL 元数据锁** | Metadata Lock (MDL) | 当你对表结构执行 `ALTER TABLE` 时，MySQL 会申请写锁以保证元数据一致性。在大表变更或高并发业务期间极易阻塞常规的增删改查。 | 03.02.02 |
| **业务唯一键** | `UNIQUE KEY` | 将业务唯一性下沉到数据库，避免并发写入绕过应用层检查。 | 03.02.03 |
| **外键与逻辑外键** | `FOREIGN KEY` / 应用维护 | 在一致性保障、写入成本和服务边界之间做明确取舍。 | 03.02.04 |
| **多对多关联表** | 联合主键与两个外键 | 将 M:N 关系拆成两个 1:N，保证组合关系不重复。 | 03.02.05 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

> 快速查阅本章最常用的命令、最佳实践或最容易踩坑的设定。

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| **创建测试/正式数据库** | `CREATE DATABASE IF NOT EXISTS order_system;` | 绝不能写成无条件的 `CREATE DATABASE`。如果其他协作者已经在 Docker 或本地建了库，再次运行会抛出 `Database exists` 报错阻断整个脚本。 |
| **修改默认排序规则** | `ALTER DATABASE my_db COLLATE utf8mb4_bin;` | 修改后必须明白这不会对既有的表结构生效。已有的表和列字符集必须单独写 `ALTER TABLE` 升级。 |
| **生产大表结构修改** | 小心使用 `ALTER TABLE ... ADD COLUMN` | 大表的结构变更在不支持 Instant DDL 的老版本中会锁表并重建整张表，可能耗时数小时。生产环境变更必须确认表容量和引擎支持情况，必要时采用第三方 Online 变更工具。 |
