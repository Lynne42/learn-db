# 模块 03.06: TCL — 事务控制语言

> **模块定位**：单条 SQL 正确不等于业务操作正确。下单会同时修改库存、订单和订单明细，TCL 将多条语句组织为一个不可分割的工作单元，避免系统停在“扣了库存却没有订单”的中间状态。

## 🎯 知识边界与生态位

**本模块覆盖：**

- ACID 四个属性及其职责边界。
- `START TRANSACTION`、`COMMIT`、`ROLLBACK`。
- `SAVEPOINT` 与局部回滚。
- `autocommit` 的默认行为。
- 订单、明细和库存的原子写入。

**本模块不覆盖：**

- 隔离级别、MVCC、锁、死锁与并发控制，将在 04.03 系统展开。
- redo log、undo log、binlog 的内部实现与崩溃恢复细节。
- 分布式事务、Saga 和最终一致性。

## 🗺️ 完整知识地图 (Knowledge Map)

| 核心知识点 | 本质/语法 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **Atomicity** | 全部成功或全部回滚 | 消除多表写入的半完成状态。 | 03.06.00 |
| **Consistency** | 约束与业务不变量 | 事务前后数据必须满足库存、外键和金额规则。 | 03.06.00 |
| **Isolation** | 并发事务相互隔离 | 控制脏读、不可重复读、幻读和写冲突。 | 03.06.00 |
| **Durability** | 提交结果持久化 | `COMMIT` 成功后，崩溃恢复仍应保留结果。 | 03.06.00 |
| **事务边界** | `START TRANSACTION` / `COMMIT` / `ROLLBACK` | 边界应与一个业务不变量对齐，避免过大或过碎。 | 03.06.00 |
| **局部回滚** | `SAVEPOINT` | 在长事务内撤销后半段操作，但不会释放所有事务成本。 | 03.06.00 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| 开启事务 | `START TRANSACTION` | 不要假设关闭 `autocommit` 是唯一开启方式。 |
| 成功提交 | `COMMIT` | 应用必须确认所有业务条件成立后再提交。 |
| 失败回滚 | `ROLLBACK` | SQL 报错不代表 MySQL 自动回滚整个事务。 |
| 局部撤销 | `SAVEPOINT name` / `ROLLBACK TO name` | Savepoint 不能替代清晰的事务边界。 |
| 库存扣减 | `UPDATE ... SET stock = stock - ? WHERE stock >= ?` | 先查后改存在并发窗口，应使用条件更新并检查影响行数。 |
| DDL 混入事务 | 避免在业务事务中执行 DDL | 多数 DDL 会触发 Implicit Commit，破坏预期回滚边界。 |
