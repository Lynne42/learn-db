# 模块 03.05: DCL — 数据控制语言

> **模块定位**：DDL、DML、DQL 解决了对象、数据和查询问题，但生产系统不能让所有连接都以 `root` 运行。DCL 负责建立数据库身份边界，并以最小权限控制账户能访问哪些对象、执行哪些动作。

## 🎯 知识边界与生态位

**本模块覆盖：**

- MySQL 账户的 `'user'@'host'` 身份模型。
- `CREATE USER`、认证凭据与账户创建边界。
- `GRANT`、`REVOKE` 和 `SHOW GRANTS`。
- 全局、数据库、表与列级权限范围。
- 订单系统只读报表账户的最小权限设计。

**本模块不覆盖：**

- 密码轮换、TLS、审计、动态权限和生产安全基线，将在 05.03 用户权限与安全展开。
- 角色的复杂编排与组织级权限治理。
- 云数据库 IAM、Proxy 和 Secret Manager 集成。

## 🗺️ 完整知识地图 (Knowledge Map)

| 核心知识点 | 本质/语法 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **账户身份** | `'user'@'host'` | 用户名与来源主机共同构成身份；同名不同 host 是不同账户。 | 03.05.00 |
| **认证与授权分离** | `CREATE USER` / `GRANT` | 先证明“你是谁”，再判断“你能做什么”，降低职责混淆。 | 03.05.00 |
| **权限范围** | `*.*` / `db.*` / `db.table` | 范围越大，误操作与凭据泄露的爆炸半径越大。 | 03.05.00 |
| **权限回收** | `REVOKE` | 权限生命周期必须可收缩，离职、服务下线和职责变化都需要回收。 | 03.05.00 |
| **权限审计** | `SHOW GRANTS` | 以最终有效授权为事实来源，避免仅依赖部署脚本推断当前状态。 | 03.05.00 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| 创建账户 | `CREATE USER 'name'@'host' IDENTIFIED BY 'secret'` | `'name'@'localhost'` 与 `'name'@'%'` 不是同一账户。 |
| 库级只读 | `GRANT SELECT ON db_name.* TO 'name'@'host'` | 不要为只读服务授予 `ALL PRIVILEGES`。 |
| 回收写权限 | `REVOKE INSERT ON db_name.* FROM 'name'@'host'` | `REVOKE` 不会删除账户。 |
| 查看授权 | `SHOW GRANTS FOR 'name'@'host'` | 检查实际结果，不以“应该已授权”替代验证。 |
| 删除账户 | `DROP USER 'name'@'host'` | 先确认连接方已迁移，避免直接中断业务。 |
