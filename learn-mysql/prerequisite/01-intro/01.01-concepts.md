## ⚡ 速查摘要

- **数据库三大核心能力**：极速查询（索引）、并发控制（锁）、崩溃恢复（事务日志），这是普通文件系统无法做到的。
- **关系型 (RDBMS)**：以强结构的二维表格存储数据，强调强一致性（如 MySQL、PostgreSQL）。
- **非关系型 (NoSQL)**：键值对或文档形式存储，强调极致性能或结构扩展性（如 Redis、MongoDB）。
- **ACID 事务**：原子性(A)、一致性(C)、隔离性(I)、持久性(D)，是金融与交易系统的基石。

## 📖 概念全景

### 1. 什么是数据库？它和文件系统有什么区别？
在最基础的层面，数据总是要保存在硬盘的文件里的（例如 TXT 或是 Excel）。但当系统面临高并发和海量数据时，直接读写文件会面临毁灭性的灾难：
- **查询瓶颈**：想从一亿行记录的文件中找一个人，必须从头遍历。
- **并发冲突**：成百上千个线程同时打开同一个文件写入，会导致文件损坏或互相覆盖。
- **数据损坏**：写入进行到一半时服务器突然断电，文件状态将被彻底破坏。

**数据库管理系统（DBMS）** 就是封装在操作系统文件系统之上的专业中间件。它通过 **索引 (B+树)** 解决百亿级数据秒级查询的问题，通过 **锁机制** 控制并发写入，通过 **Redo/Undo 日志** 保证即便突然断电数据也绝对不丢。

### 2. 主流数据库生态位全景图
当今服务端架构中，通常会混用多种数据库来各司其职：

1. **关系型数据库 (RDBMS - 事实基准)** 
   - **代表**：MySQL、PostgreSQL、Oracle
   - **特点**：数据以严谨的“行与列”的表格形式存在，表与表之间有明确的关联关系。
   - **场景**：存储不可丢失的核心业务数据（资产、交易记录、核心实体属性）。

2. **键值内存数据库 (KV NoSQL - 极致加速)**
   - **代表**：Redis、Memcached
   - **特点**：全内存读写，极高吞吐量，但断电易丢失。
   - **场景**：高频缓存、秒杀排队、排行榜。

3. **文档型数据库 (Document NoSQL - 动态扩展)**
   - **代表**：MongoDB
   - **特点**：以 JSON 格式存储，无需预先定义表结构。
   - **场景**：爬虫数据、游戏日志、结构多变的用户评价。

### 3. 核心基石：ACID 事务模型
关系型数据库之所以能胜任金融交易，是因为它遵守 ACID 准则：
- **A - Atomicity (原子性)**：一组操作（如扣减库存 + 创建订单）被视为一个不可分割的整体，要么全部成功执行，要么全部撤销（回滚）。
- **C - Consistency (一致性)**：事务执行前后，数据必须满足所有的逻辑约束，从一个合法状态转移到另一个合法状态。
- **I - Isolation (隔离性)**：并发执行的多个事务之间互不干扰。
- **D - Durability (持久性)**：一旦系统提示“提交成功”，哪怕下一秒机房断电被烧，重启后数据就一定在。

### 4. MySQL 宏观架构全景图
作为一个优秀的架构师，你必须知道当你敲下一条 SQL 并回车时，MySQL 内部到底发生了什么。MySQL 采用经典的**插件式三层架构**：
1. **连接层 (Connection Layer)**：负责处理客户端的连接请求、身份认证（你输入的密码对不对）和连接池管理。
2. **服务层 (Service Layer)**：大脑。包含 SQL 接口、**解析器 (Parser)**（检查语法对不对）、**优化器 (Optimizer)**（决定走哪个索引最快）。
3. **引擎层 (Storage Engine Layer)**：手脚。真正负责把数据写进磁盘或者从磁盘读出来。MySQL 最牛的设计就是**插件式存储引擎**，最常见的就是 **InnoDB**（支持事务和行级锁，默认王者）和 **MyISAM**（不支持事务，已被淘汰）。

### 5. SQL 标准与 MySQL 方言
SQL（结构化查询语言）是一套国际标准（如 SQL-92, SQL:2003）。但每个数据库厂商都会在标准之上加入自己的“方言”以提供更强大的功能。
例如在 MySQL 中：
- 有很多独家好用的函数（如 `GROUP_CONCAT`）。
- 默认大小写敏感规则与操作系统强相关（Linux 敏感，Windows 不敏感）。
了解“方言”的存在，能帮助你在未来进行异构数据库迁移（如 MySQL 迁往 PostgreSQL）时避开巨大的深坑。

## 💻 SQL 语法（热身）

今天我们不建表，只学习如何用 SQL 与数据库引擎进行最基础的“握手”对话：

```sql
-- 查询数据库引擎的当前版本
SELECT VERSION();

-- 连通性测试：让数据库引擎帮你做一个简单的运算并回显
SELECT 1 + 1 AS result;

-- 连通性测试：回显一段指定的字符串
SELECT 'Hello MySQL' AS message;
```

## ⚠️ 常见坑点

- **遗漏分号**：在标准的命令行 SQL 客户端中，所有的 SQL 语句必须以分号 `;` 结尾。如果不敲分号直接回车，终端会换行（显示 `->`）并一直等待你的后续输入。
