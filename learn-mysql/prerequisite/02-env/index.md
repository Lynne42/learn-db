# 模块 02: 环境搭建与工具

> **模块定位**：工欲善其事，必先利其器。本模块将带你彻底搞懂你刚刚启动的 Docker 环境到底是怎么运作的，以及如何熟练使用命令行工具与 MySQL 对话。掌握这些基建能力，你才算真正在服务器上安了家。

## 🎯 知识边界与生态位

**本模块覆盖**：
- `docker-compose.yml` 核心配置解析（镜像、端口、环境变量）。
- 容器化数据库的生命线：Volume 数据卷持久化机制映射。
- MySQL 官方镜像的 `docker-entrypoint-initdb.d` 自动初始化特性。
- `mysql` 命令行客户端基础用法与认证连通测试。

**本模块不覆盖**：
- Docker 底层的 cgroup 和 namespace 原理。
- MySQL 生产级的高可用/主从复制 Docker 拓扑（见【模块 25】）。
- 如何用 SQL 建表（见【模块 06】）。

## 🗺️ 完整知识地图 (Knowledge Map)

> 从架构师的视角，重新梳理本章知识点的因果关系。

| 核心知识点 | 本质/机制 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **Docker 容器** | 隔离的无状态进程 | 消除环境依赖地狱。不管是谁的电脑，拉取同样的镜像，跑出来的 MySQL 环境绝对一致。 | 02.01 |
| **Volume 持久化** | `宿主机目录 : 容器目录` 映射 | 容器是随时被摧毁的，必须把数据引流到物理硬盘（如 `./data/mysql`）上，否则重启就删库。 | 02.01 |
| **端口映射** | `本机暴露端口 : 内部运行端口` | 打破容器的次元壁，让本机的 GUI 或代码能够顺利连接到容器内部的 3306 端口。 | 02.01 |
| **Initdb 自动初始化** | 启动脚本注入 | 放置在特定目录的 `.sql` 脚本会在容器首次初始化数据目录时自动执行，是快速搭建开发环境的神器。 | 02.01 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

> 快速查阅本章最常用的命令、最佳实践或最容易踩坑的设定。

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| **排查容器报错** | `docker logs mysql-learn` | 容器如果出现 Crash Loop（如 MySQL 8.4 废弃了旧版密码插件），千万别瞎猜，第一时间看日志。 |
| **销毁并重建环境** | `docker compose down` <br/> `rm -rf ./data` <br/> `docker compose up -d` | **极其危险！** 在本地开发时可以用 `rm -rf` 重新初始化脏数据；在生产环境中绝对禁止删除映射的物理数据目录！ |
| **连接数据库** | 留待 02.02 讲解 | 注意区分宿主机映射的端口和容器内默认端口的区别，使用客户端连接时务必填**冒号左边**暴露的端口。 |
