# 模块 02.01: 数据类型

> **模块定位**：学习数据库时，核心也是选用正确的数据类型。合理的数据类型能够保障精度、优化存储和索引性能，是建表的基本功。本模块将解构 MySQL 的数值、字符串、日期时间及原生 JSON 类型，带你像架构师一样进行数据存储设计。

## 🎯 知识边界与生态位

**本模块覆盖**：
- 整数类型（TINYINT, INT, BIGINT）的取值范围、存储空间及 `UNSIGNED` 属性。
- 浮点数（FLOAT, DOUBLE）与定点数（DECIMAL）在精度敏感场景（如价格金额）中的选型差异及底层原因。
- 字符串类型（CHAR, VARCHAR, TEXT, BLOB）的定长与变长性能差异及溢出存储。
- ENUM 与 SET 的设计原理、在状态机表达中的优势与使用陷阱。
- 日期时间类型（DATE, TIME, DATETIME, TIMESTAMP）的取值区间、默认值设置及 `TIMESTAMP` 独特的时区自动转换特性。
- 半结构化数据存储：MySQL 原生 `JSON` 类型及其检索验证基础。

**本模块不覆盖**：
- 数据类型隐式转换导致的索引失效问题（详见【模块 04.02】）。
- 针对大文本字段的全文检索优化（详见【模块 04.02】）。
- JSON 虚拟生成列的高级索引优化（详见【模块 04.02】）。

## 🗺️ 完整知识地图 (Knowledge Map)

> 从架构师的视角，重新梳理本章知识点的因果关系。

| 核心知识点 | 本质/语法 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **DECIMAL 金额表示** | `DECIMAL(M,D)` 定点数 | 浮点数有精度偏差！当保存钱款、结算数据时，必须使用 DECIMAL 以避免尾数舍入漏洞。 | 02.01.00 |
| **无符号整型** | `INT UNSIGNED` | 当确认数据绝不为负数（如主键自增、商品库存、用户积分）时，使用无符号类型可以将正数取值上限扩大一倍。 | 02.01.00 |
| **变长 VARCHAR** | `VARCHAR(N)` | 存储实际字符加长度标记。对于长度波动且不确定的中短字段（如邮箱、密码哈希），应优选 VARCHAR 节约空间。 | 02.01.01 |
| **大字段溢出** | `TEXT / BLOB` | 超长文本和二进制字段通常不存放在数据页内部，而是使用行溢出页存放。应尽量避免对其进行频繁的 `SELECT *` 以免影响 IO。 | 02.01.01 |
| **时区感知类型** | `TIMESTAMP` | 占用 4 字节，由 UTC 转换。如果系统是跨国服务，需要自动适配当前时区，记录创建修改时间推荐使用它。 | 02.01.02 |
| **远期未来日期** | `DATETIME` | 占用 5 或 8 字节。因 TIMESTAMP 在 2038 年达到上限（2038年问题），对于未来的合同截止日、会员到期日等，必须使用 DATETIME。 | 02.01.02 |
| **半结构化存储** | `JSON` | 适用于属性经常变更、极少做复杂聚合的商品非主线扩展规格。但不应对其频繁做 DML，应按需将频繁过滤的键转换为虚拟列。 | 02.01.03 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

> 快速查阅本章最常用的命令、最佳实践或最容易踩坑的设定。

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| **高额金钱存储** | `DECIMAL(10,2)` 或以 `分` 为单位整型 | 绝对严禁使用 FLOAT 或 DOUBLE 保存价格。浮点数的精度损失会让财务账单最终对不齐。 |
| **超长自增主键** | `id BIGINT UNSIGNED AUTO_INCREMENT` | 高并发或大规模日志写入表如果选用 `INT`，最大上限 21 亿行极易耗尽溢出，发生溢出时会引发主键冲突 Crash。高并发写入必须使用 `BIGINT`。 |
| **时区差异踩坑** | 对比物理服务器时区设置 | `TIMESTAMP` 随 MySQL 连接的时区转换，而 `DATETIME` 不会。在多机房分布式的异地部署中，注意统一连接的时区，防止读取出来的时间“凭空多出/减少数小时”。 |
| **ENUM 增删缺陷** | 使用逻辑判断或关联表替代 ENUM | 每次在 ENUM 列增加一个状态值，都需要发起一次表结构变更（DDL）。大表 DDL 会导致锁表或生成大量临时文件，应当极力避免。 |
