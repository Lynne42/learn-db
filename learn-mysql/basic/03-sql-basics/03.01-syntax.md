# 03.01 基础语法与结构

> **故事线与承上启下**：
> *经过先导篇的环境折腾，你现在终于坐到了数据库的控制台前。准备大展拳脚的你，突然发现给订单表起个名字叫 `order` 都会疯狂报错。就像学 Python 要先懂缩进，学 C 要懂分号，学 SQL 第一步，我们必须摸透它独特的“标点符号”和“词法规则”。*

## ⚡ 速查摘要

- **反引号 (```)**：用于包裹表名、列名等“标识符”，防止与系统保留字冲突。
- **单引号 (`'`)**：用于包裹真正的“字符串字面量”。
- **注释**：`-- ` (注意有空格)、`#` (单行)、`/* */` (多行)。
- **变量体系**：`@var` (用户自己定义的会话变量)、`@@var` (MySQL 系统内置的全局或会话控制变量)。

## 🎯 学习目标 + 验收标准

- **目标**：彻底分清何时用反引号、何时用单引号；掌握会话变量的声明与传递，了解系统变量的查询方式。
- **验收标准**：能够使用 `SET` 语句定义一个用户变量，并在紧接着的 `SELECT` 中正确使用它和反引号列名。

## 📖 概念全景

### 1. 标识符与“反引号”的救赎
在建立电商系统时，如果你试图创建一个叫 `order` 的表，MySQL 会当场翻脸。因为 `ORDER` 是 SQL 语法里的保留关键字（用于 `ORDER BY` 排序）。

**【解决方案：反引号 ` 】**
反引号（键盘左上角波浪号那个键）是 MySQL 专门用来包裹**标识符（数据库名、表名、列名）**的符号。它在明确告诉解析器：“别管它是不是关键字，它只是个名字而已”。

```sql
-- 错误写法，会报错
CREATE TABLE order ...

-- 正确写法
CREATE TABLE `order` ...
SELECT `id`, `name` FROM `users`;
```
*(最佳实践：为了避免心智负担，很多 ORM 框架在底层生成 SQL 时，都会霸道地给所有表名和列名都加上反引号。)*

### 2. 字面量与严格的单引号
字面量 (Literal) 就是你在 SQL 里硬编码的固定值：数字、布尔、字符串、NULL。
其中最容易让新手翻车的是**字符串**。

在 SQL 标准中，**字符串必须且只能用单引号 (`'`) 包裹**！
虽然 MySQL 容忍你使用双引号（`"`），但如果你把带有双引号的 SQL 放到 Oracle 或 PostgreSQL 里去跑，大概率会直接爆炸。
```sql
-- ✅ 最佳实践
SELECT 'Hello World';

-- ❌ 极其不推荐，破坏了 SQL 标准兼容性
SELECT "Hello World";
```

### 3. 三种注释风格
在排查故障时，我们经常需要把某段 SQL 临时注释掉。
- `#`：MySQL 特有的单行注释（最常用、最安全）。
- `-- `：SQL 标准的单行注释。**注意：第二个横杠后面必须有一个空格**！否则在某些场景下会被识别为减号运算符！
- `/* ... */`：多行注释，适合写长篇大论的文档说明。

### 4. 变量体系：@ 与 @@
SQL 不仅仅能做增删改查，它也是一门“编程语言”，自然拥有变量机制。

#### A. 用户自定义变量 (`@`)
它的作用域是**当前连接会话 (Session)**。只要你不断开连接，这个变量里的值就一直在。常用于复杂的游标流转或自动化脚本中传递数据。

```sql
-- 赋值
SET @user_role = 'Admin';
SET @max_price = 99.99;

-- 使用
SELECT @user_role;
```

#### B. 系统变量 (`@@`)
这是用来控制 MySQL 引擎脾气和行为的超级开关。
有些是全局的（影响所有连接），有些是会话的（只影响当前连接）。

```sql
-- 查看当前数据库的端口
SELECT @@port;

-- 查看所有带 timeout 的系统变量
SHOW VARIABLES LIKE '%timeout%';
```

## 🏗️ 项目实战 —— 订单系统场景

作为电商系统的架构师，在正式导入数据前，你习惯性地先写一段探针 SQL 来测试你的客户端环境，同时复习一下 SQL 的词法规范。
你在脚本里写道：

```sql
-- 设置一个模拟的折扣变量
SET @discount_rate = 0.8;

-- 尝试用反引号命名一个带空格的奇葩列名，并计算打折后的价格
SELECT 100 * @discount_rate AS `Final Price`;
```
完美运行！这证明你完全搞懂了 `@` 和 ``` 的区别。

## ⚠️ 常见坑点

- **用 `=` 在 `SELECT` 中赋值**：
  在 `SET @a = 1;` 中，`=` 是赋值符号。
  但是如果你想在 `SELECT` 语句里顺手给变量赋值，**必须使用 `:=`**！因为在 `SELECT` 里，`=` 永远会被优先解析为“比较是否相等”的逻辑运算符（返回 0 或 1）。
  *示例：`SELECT @a := 10;`*

## 🚀 延伸与深度学习

> 架构之路永无止境。如果你对本节内容意犹未尽，以下是为你精选的深度拓展方向，供你在未来进阶时探索：

- **SQL 模式 (sql_mode)**：它是系统变量中最核心的一个（`@@sql_mode`）。它决定了 MySQL 是否开启严格模式（比如插入过长字符串是直接报错还是悄悄截断）。在 MySQL 8.0 中，严格模式默认是全面开启的。
- **用户变量的并发安全**：用户变量 `@var` 并不是线程安全的。如果你把它用在应用程序的连接池里（比如 Java 的 HikariCP），极有可能发生数据串联和污染。因此它更适合在单一批处理脚本中使用。
- **信息模式 (INFORMATION_SCHEMA)**：比起用 `SHOW VARIABLES`，更底层的做法是直接查询系统自带的内存数据库 `information_schema` 里的表。
