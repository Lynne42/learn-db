# 模块 03: SQL 语言基础

> **模块定位**：欢迎来到【基础篇】！在建造高楼大厦之前，我们需要先熟悉砖块的材质。本模块将脱离具体的增删改查，从纯语言设计的视角，带你解剖 SQL 的基础词法、语法元素以及变量机制。

## 🎯 知识边界与生态位

**本模块覆盖**：
- 标识符的命名规范与反引号 (```) 转义机制。
- 三种注释风格（`--`, `#`, `/* */`）的适用场景。
- 字面量解析，特别是对 `NULL` 的初步认知。
- 运算符优先级与表达式执行。
- 用户自定义变量（`@var`）与 MySQL 系统全局变量（`@@var`）的区别与基础操作。

**本模块不覆盖**：
- 库表的创建（见【模块 06】）。
- `SELECT` 语句的复杂条件过滤与连表（见【模块 09】与【模块 11】）。
- 存储过程中的局部变量 `DECLARE`（见【模块 18】）。

## 🗺️ 完整知识地图 (Knowledge Map)

> 从架构师的视角，重新梳理本章知识点的因果关系。

| 核心知识点 | 本质/语法 | 架构师视角 (Why & When) | 学习位置 |
|------------|-----------|-------------------------|----------|
| **反引号转义** | ``` `order` ``` | 当不得不使用数据库保留字（如 `order`, `desc`）作为列名时，强制引擎将其识别为普通标识符的保命机制。 | 03.01 |
| **单引号与双引号** | `'string'` | SQL 标准严格规定字符串必须用单引号。虽然 MySQL 容忍双引号，但为了兼容性，永远只用单引号。 | 03.01 |
| **NULL 的特殊性** | `NULL` | 它不是零，不是空字符串，它是“未知”。理解 NULL 的传染性是写出健壮聚合查询的前提。 | 03.01 |
| **用户变量** | `SET @uid = 1;` | 会话级存储。在复杂的存储过程或自动化修数脚本中，用于在多条 SQL 语句之间传递状态。 | 03.01 |
| **系统变量** | `SELECT @@port;` | 控制整个数据库引擎行为的开关（如最大连接数、隔离级别）。是 DBA 性能调优的核武器。 | 03.01 |

## ⚡ 速查与避坑指南 (Cheat Sheet)

> 快速查阅本章最常用的命令、最佳实践或最容易踩坑的设定。

| 场景/操作 | 最佳实践 / 核心命令 | ⚠️ 常见避坑提示 |
|-----------|--------------------|----------------|
| **写注释** | `-- 这是一个注释` | `--` 后面**必须**跟一个空格，否则 MySQL 有时会报错。安全起见可以多用 `#`。 |
| **变量赋值** | `SET @x = 10;` | 在 `SELECT` 中给变量赋值必须使用 `:=`，因为 `=` 在 `SELECT` 中会被解析为判断相等的比较运算符！ |
| **查看系统配置** | `SHOW VARIABLES LIKE '%timeout%';` | 了解当前系统变量是日常排查（如锁等待超时、连接超时的）第一步。 |
